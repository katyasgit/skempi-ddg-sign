# Предсказание знака ddG по данным SKEMPI 2.0

Тестовое задание: простая модель машинного обучения, которая предсказывает
знак изменения свободной энергии связывания (ddG) при мутациях в
белок-белковых комплексах. Ниже — ход рассуждений по шагам: как я понимаю
задачу, как готовлю данные, какие беру признаки, как честно оцениваю модель
и что получилось.

## 1. Задача своими словами

Два белка образуют комплекс; прочность связывания описывается свободной
энергией связывания ΔG — чем она ниже, тем прочнее комплекс. Мутация в одном
из белков меняет эту энергию:

**ddG = ΔG(мутант) − ΔG(дикий тип)**

- ddG > 0 — мутация **ослабляет** связывание (дестабилизирующая);
- ddG < 0 — мутация **усиливает** связывание (стабилизирующая).

То есть задача сводится к бинарной классификации: по описанию мутации
предсказать, ослабит она комплекс или усилит.

## 2. Данные: из Kd в ddG

[SKEMPI 2.0](https://life.bsc.es/pid/skempi2) — база экспериментальных
измерений аффинности для белок-белковых комплексов с известной структурой:
7085 записей вида «комплекс + мутация(и) + константа диссоциации Kd мутанта
и дикого типа». Готового ddG в базе нет, поэтому считаю его из Kd:

ΔG = R·T·ln(Kd), откуда **ddG = R·T·ln(Kd_mut / Kd_wt)**, ккал/моль
(температура — из записи, если её нет — 298 K).

Дальше три решения по чистке:

1. **Записи без измеренной аффинности** мутанта или дикого типа выбрасываю —
   для них ddG не посчитать (7085 → 6798).
2. **Дубликаты.** Одна и та же мутация часто измерена в нескольких работах.
   Оставляю одну запись на пару «комплекс + мутация» с медианным ddG — иначе
   одинаковые примеры могут одновременно оказаться в train и в test и
   завысить оценку (6798 → 5914).
3. **ddG = 0** — знак не определён, такие записи убираю (5914 → 5763).

Итог: **5763 записи из 341 комплекса**; 78% мутаций дестабилизирующие —
классы заметно несбалансированы, это учитываю дальше и в моделях
(`class_weight`), и в выборе метрик (balanced accuracy, ROC-AUC).

## 3. Признаки

Сознательно беру только простые признаки, которые извлекаются из самой
таблицы, без обработки 3D-структур — задание просит показать обучаемость,
а не выжать максимум качества. На каждую запись:

- **какие аминокислоты заменяются и на что** — счётчики по 20 аминокислотам
  для дикого типа и для мутанта (40 признаков);
- **физико-химические сдвиги** «мутант минус дикий тип»: гидрофобность
  (шкала Кайта — Дулиттла), объём остатка (Zamyatnin), формальный заряд;
- **положение мутации относительно интерфейса** — аннотация SKEMPI
  (COR — ядро интерфейса, SUP — опора, RIM — край, INT — внутри белка,
  SUR — поверхность). Интуиция: мутация в ядре интерфейса бьёт по
  связыванию сильнее, чем на удалённой поверхности;
- **число мутаций** в записи (есть одиночные и множественные).

Всего 49 признаков. Записи с множественными мутациями не выбрасываю:
счётчики и сдвиги просто суммируются по всем мутациям записи.

## 4. Как честно оценить модель — главное решение

В SKEMPI у одного комплекса бывают десятки и сотни мутаций. При обычном
случайном разбиении мутации одного и того же комплекса попадают и в train,
и в test — модель может «запомнить» комплекс, и оценка окажется завышенной
(классическая утечка данных в задачах про белки).

Поэтому оцениваю **5-кратной кросс-валидацией GroupKFold с группировкой по
PDB-комплексу**: все мутации одного комплекса целиком уходят либо в train,
либо в test, и модель всегда проверяется на комплексах, которых не видела.
Сюда же работает и склейка дубликатов медианой из шага 2.

## 5. Модели

Три модели по нарастанию сложности (`src/train.py`):

1. **Baseline** — всегда отвечает самым частым классом. Это планка «модель
   ничему не научилась»: из-за дисбаланса её accuracy уже 0.78, поэтому
   смотреть только на accuracy нельзя.
2. **Логистическая регрессия** со стандартизацией признаков и
   `class_weight="balanced"` — простейшая линейная модель.
3. **Случайный лес** — умеет ловить нелинейности и взаимодействия признаков,
   почти не требует настройки.

## 6. Результаты: модель обучается

Метрики по кросс-валидации (среднее ± ст. отклонение по 5 фолдам, полная
таблица также в [results/metrics.md](results/metrics.md)):

| Модель | Accuracy | Balanced accuracy | F1 | ROC-AUC |
|---|---|---|---|---|
| Baseline (частый класс) | 0.779 ± 0.022 | 0.500 ± 0.000 | 0.876 ± 0.014 | 0.500 ± 0.000 |
| Логистическая регрессия | 0.624 ± 0.027 | 0.609 ± 0.019 | 0.724 ± 0.028 | 0.664 ± 0.027 |
| Случайный лес | 0.695 ± 0.022 | 0.616 ± 0.017 | 0.794 ± 0.020 | 0.685 ± 0.017 |

Что здесь важно:

- у baseline accuracy высокая (0.78), но balanced accuracy и ROC-AUC ровно
  0.5 — он не различает классы вообще;
- обе настоящие модели уверенно выше 0.5 по balanced accuracy и ROC-AUC на
  **незнакомых комплексах** — то есть выучивают обобщаемую закономерность,
  а не запоминают данные.

Кривая обучения — прямая демонстрация обучаемости: качество на отложенных
комплексах монотонно растёт с объёмом обучающей выборки, а разрыв между
train и validation сокращается (переобучение уменьшается):

крупного гидрофобного остатка в ядре интерфейса на маленький (классический

## 7. Ограничения и что можно улучшить

Качество здесь заведомо скромное — по условию им можно пренебречь. Если бы
задача была «сделать хорошо», я бы двигалась так:

- **структурные признаки**: SKEMPI даёт PDB-структуры комплексов — можно
  считать изменение доступной растворителю площади (ΔSASA), контакты
  остатка, упаковку окружения;
- **эмбеддинги белковых языковых моделей** (например, ESM-2) вместо
  или вдобавок к ручным признакам;
- **регрессия величины ddG** вместо классификации знака — информации в
  данных больше, а знак получается порогом;
- **нейтральная зона**: |ddG| < 0.5 ккал/моль сравнимо с ошибкой
  эксперимента, такие записи можно исключать из обучения или выделять в
  третий класс;
- подбор гиперпараметров (здесь модели почти «из коробки») и калибровка
  вероятностей;
- более строгие сплиты — например, по семействам белков (в SKEMPI есть
  готовые колонки `Hold_out_type` / `Hold_out_proteins`).

## Как запустить

Нужен Python 3.10+.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python src/download_data.py     # скачивает skempi_v2.csv (~1.6 МБ)
python src/prepare_dataset.py   # ddG, метки, признаки -> data/processed/
python src/train.py             # метрики и графики -> results/
```

Результаты (метрики и графики) уже закоммичены в `results/`, так что их
видно прямо в репозитории без запуска.
